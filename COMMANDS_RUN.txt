==============================================================================
 COMMANDS_RUN — the command pairs actually used on this rig
==============================================================================
 Start the RECEIVER first in every pair. The source dials/listens for the ACK,
 so a transmitter started first just burns its retry budget.
==============================================================================


------------------------------------------------------------------------------
 0. SURVEY FIRST (prepare.sh) — receive-only, nothing transmits
------------------------------------------------------------------------------
 Run on every radio that RECEIVES, with the SAME --subdev/--ant that radio will
 receive on. Writes the carrier, receive gain, det-mult and sync-threshold into
 searching/, where radio.sh and run.sh read them.

# WINGS_LAB X310s — with rf ACK both boxes receive, so survey BOTH
./prepare.sh --device x310 --args addr=192.168.40.2 --subdev A:0 --ant RX2 --band vert2450
./prepare.sh --device x310 --args addr=192.168.30.2 --subdev A:0 --ant RX2 --band vert2450

# EdgeAI_Lab B210 — only 30CD3F7 receives
./prepare.sh --device b210 --args serial=30CD3F7 --subdev A:B --ant TX/RX --band vert900

# the carriers it found
cat "$(ls -t /workspace/experiments/searching/freqs-*.json | head -1)"

# check it landed where the run will look for it
python3 union/phy_profile.py --args serial=30CD3F7 --subdev A:B --ant TX/RX

 --subdev/--ant MUST match the receive path. A profile is keyed by signal path
 (serial + band + subdev + antenna), so surveying A:A/RX2 and then receiving on
 A:B/TX-RX files the measurement where nothing will look for it.
 --band cannot be probed: vert900 824-960, ism915 902-928, vert2450 2400-2480,
 vert2450-5g 4900-5900. The wrong one measures the antenna, not the band.
 A transmitter is never surveyed — its own noise says nothing about what the far
 end hears. It takes the carrier from the receiver's survey.
 After this --det-mult, --sync-threshold and --rx-gain are optional: the profile
 supplies them. Section 1 still types them, and a typed value always wins.


------------------------------------------------------------------------------
 1. WINGS_LAB/UB-OAI-5G testbed TWO X310s — data over the air, ACK over the air  (--ack-transport rf)
------------------------------------------------------------------------------

# ── SINK box (the X310 at .40.2) — start this first ──
./radio.sh rx --device x310 \
  --args addr=192.168.40.2 --rx-args addr=192.168.40.2 --tx-args addr=192.168.40.2 \
  --rx-subdev A:0 --rx-ant RX2   --rx-freq 2400e6 --rx-gain 10 \
  --tx-subdev A:0 --tx-ant TX/RX --tx-freq 2450e6 --tx-gain 31.5 \
  --role sink_arq --ack-transport rf \
  --det-mult 30 --sync-threshold 10 --scheme QPSK --bytes-length 8000

# ── SOURCE box (the X310 at .30.2) ──
./radio.sh tx --device x310 \
  --args addr=192.168.30.2 --tx-args addr=192.168.30.2 --rx-args addr=192.168.30.2 \
  --tx-subdev A:0 --tx-ant TX/RX --tx-freq 2400e6 --tx-gain 31.5 \
  --rx-subdev A:0 --rx-ant RX2   --rx-freq 2450e6 --rx-gain 10 \
  --role source_arq --ack-transport rf --max-attempts 0 \
  --det-mult 30 --sync-threshold 10 --scheme QPSK --bytes-length 8000


 ------------------------------------------------------------------------------
 2. EdgeAI_Lab/LoRa-Testbed TWO B210s on ONE machine — data over the air, ACK over TCP  (as run)
------------------------------------------------------------------------------

# ── SINK (B210 30CD3F7) — start this first ──
./radio.sh rx --device b210 --args serial=30CD3F7 \
  --rx-subdev A:B --rx-ant TX/RX --rx-freq 915e6 \
  --role sink_arq --ack-transport tcp --ack-port 5599 --scheme QPSK

# ── SOURCE (B210 30CD424) ──
./radio.sh tx --device b210 --args serial=30CD424 \
  --tx-subdev A:A --tx-ant TX/RX --tx-freq 915e6 --tx-gain 50 \
  --role source_arq --ack-transport tcp \
  --ack-host 127.0.0.1 --ack-port 5599 --max-attempts 0 --scheme QPSK
